Интерактивная образовательная платформа для глубокого изучения уязвимости **Server-Side Request Forgery (SSRF)** — одной из самых опасных веб-уязвимостей, позволяющей атакующему заставить сервер выполнять HTTP-запросы от своего имени к произвольным адресам. Стенд полностью работает в браузере без бэкенда — все сценарии эмулируются на клиенте с помощью staged-анимации запросов.

### О чём этот проект

Когда веб-приложение принимает URL от пользователя и выполняет серверный HTTP-запрос по этому адресу (загрузка изображений, вебхуки, превью ссылок, прокси), возникает вектор атаки: атакующий подставляет внутренний адрес вместо ожидаемого внешнего. Сервер, доверяя входному URL, обращается к внутренним сервисам, облачным метаданным, локальным файлам или закрытым портам — и возвращает результат атакующему. Это не теоретическая угроза: инцидент Capital One (2019) обошёлся в $190 млн, а SSRF стабильно входит в OWASP Top 10.

### Архитектура приложения

Проект построен как standalone React SPA (Vite) с полностью клиентской эмуляцией SSRF:

- **Frontend** — React 19 SPA с тремя основными разделами: Теория, Песочница (Sandbox), Справочные таблицы
- **Эмуляция SSRF** — вместо реального бэкенда используется `setTimeout` с staged-анимацией: выборка сценария → визуализация DNS → визуализация TCP → формирование ответа. Пользователь видит каждый этап атаки в реальном времени
- **8 сценариев** — каждый содержит: описание, пред-объяснение (до отправки), placeholder-URL, функцию `matchUrl()`, функцию `emulatedResponse()` с ветвлением по путям, аннотацию ответа, подробное объяснение, реальный пример из жизни и пошаговый разбор
- **Темы** — светлая и тёмная через CSS Custom Properties + React Context с сохранением в localStorage
- **Деплой** — GitHub Pages (статический хостинг, бэкенд не нужен)

### Восемь сценариев атак

| # | Сценарий | Категория | Критичность |
|---|----------|-----------|-------------|
| 1 | Чтение облачных метаданных AWS | Облако | Critical |
| 2 | Доступ к внутренней админ-панели (localhost) | Внутренние сервисы | High |
| 3 | Чтение локальных файлов (file://) | Файловая система | High |
| 4 | Сканирование внутренних портов | Разведка | Medium |
| 5 | Обход защиты через DNS Rebinding | Продвинутые техники | Critical |
| 6 | Слепой SSRF (Blind SSRF) | Продвинутые техники | Critical |
| 7 | Обход фильтров (URL Parsing Bypass) | Обход защиты | Critical |
| 8 | Эксплуатация через gopher:// (Redis RCE) | Продвинутые техники | Critical |

### Детали ключевых сценариев

**1. AWS Metadata (169.254.169.254)** — атакующий заставляет сервер обратиться к эндпойнту метаданных AWS EC2 и получить временные IAM-ключи. В песочнице эмулируется ответ с AccessKeyId, SecretAccessKey и Token. Аннотация объясняет, что с этими ключами можно сделать (S3, DynamoDB, Lambda), а реальный пример описывает инцидент Capital One: Paige Thompson через SSRF на WAF получила ключи и скачала данные 106 млн клиентов.

**5. DNS Rebinding** — демонстрируется техника обхода SSRF-фильтров через быструю смену DNS-записи: первый запрос возвращает внешний IP (проходит проверку), второй — внутренний 10.0.0.0 (выполняет атаку). Анимация показывает таймлайн DNS-ответов.

**7. URL Parsing Bypass** — таблица из 12+ техник обхода: `http://evil@127.0.0.1`, `http://0x7f000001`, `http://2130706433`, `http://[::1]`, `http://127.1`, добавление `@` перед IP, использование коротких IP, IPv6-маппинг и другие.

**8. gopher:// Redis RCE** — самый опасный сценарий: через протокол gopher атакующий отправляет произвольные TCP-команды во внутренний Redis и выполняет код на сервере (запись cronjob, webshell). В песочнице показана payload-цепочка: `gopher://10.0.1.20:6379/_*1%0d%0a...`.

### Разделы интерфейса

- **Теория** — определение SSRF с аналогией (курьер-посредник), сравнение SSRF vs CSRF (частая путаница), таблица поддерживаемых протоколов (http, https, file, gopher, dict, ftp), таблица методов обхода защиты, аккордеон с углублённым объяснением каждого аспекта, ссылки на источники (OWASP, PortSwigger, Snyk)
- **Песочница** — выбор сценария из выпадающего списка, URL-поле с placeholder, кнопка «Отправить», визуализация этапов запроса (DNS → TCP → Response), панель ответа с SyntaxHighlighter (JSON), бейдж критичности, кнопка «Объяснение» для раскрытия подробного разбора с реальными примерами
- **Справочные таблицы** — встроенный справочник: какие протоколы поддерживаются, как обходить фильтры, что можно сделать с полученными данными
- **Тёмная/светлая тема** — переключатель в хедере, сохраняется в localStorage
- **Адаптивный дизайн** — работает на мобильных, планшетах и десктопах (breakpoints: 600px, 1024px, 1200px)

### Стек технологий

- **Frontend**: React 19, Vite 8, CSS Custom Properties
- **Подсветка кода**: react-syntax-highlighter для JSON-ответов
- **Иконки**: react-icons (IoSunny, IoMoon, IoArrowUp)
- **Эмуляция**: полностью клиентская, без бэкенда — `setTimeout` с staged-анимацией
- **Деплой**: GitHub Pages (статический сайт)
