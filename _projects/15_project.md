Интерактивная лаборатория для глубокого погружения в одну из самых распространённых веб-уязвимостей — **CORS Origin Reflection**. Сервер доверяет любому источнику запроса, копируя заголовок `Origin` в `Access-Control-Allow-Origin`, и разрешает учётные данные. Результат — хакер читает приватные данные пользователя с любого домена.

### О чём этот проект

Когда API настраивают CORS по принципу «отразить Origin обратно», любой сайт в интернете получает доступ к защищённым эндпоинтам с cookies жертвы. Это не теоретическая угроза — подобные ошибки находят в продакшене крупнейших сервисов. Лаборатория позволяет своими руками увидеть, как возникает дыра, как она эксплуатируется и как правильно её закрыть.

### Что внутри

- **Переключатель режимов** — тумблер между «Уязвимым» и «Безопасным» режимом сервера. Мгновенное переключение без перезагрузки: наблюдайте, как меняется поведение API
- **API-панель** — кнопки для запросов к `/api/profile` и `/api/account` с мгновенным отображением ответа и CORS-заголовков
- **Визуализация заголовков** — наглядная таблица: какие заголовки отправляет браузер, что возвращает сервер и почему это критично
- **Страница злоумышленника** — отдельная страница `evil-phishing.com` с пошаговой имитацией атаки: JavaScript крадёт данные, логирует каждый шаг, показывает результат
- **Обучающий аккордеон** — шесть разворачивающихся разделов: что такое CORS, что такое Origin, как работает рефлексия, в чём отличие безопасной конфигурации, как защититься, разбор реальных CVE
- **Сравнительная таблица** — уязвимый vs. безопасный режим: параллельное сопоставление заголовков и поведения
- **Квиз** — проверка знаний с мгновенной обратной связью и пояснениями к каждому ответу
- **Примеры кода** — фрагменты JavaScript для клиента и сервера с комментариями
- **Ссылки на источники** — MDN, OWASP, PortSwigger и другие материалы для углублённого изучения

### Как работает уязвимость

1. Браузер отправляет запрос с заголовком `Origin: https://evil-phishing.com`
2. Сервер копирует это значение: `Access-Control-Allow-Origin: https://evil-phishing.com`
3. Сервер добавляет: `Access-Control-Allow-Credentials: true`
4. Браузер разрешает JavaScript на злоумышленническом сайте прочитать ответ
5. Хакер получает email, баланс, номер счёта — всё, что доступно через API

В безопасном режиме сервер сверяет `Origin` с белым списком разрешённых доменов и отклоняет запросы с неизвестных источников.

### Стек технологий

- **Frontend**: Next.js 16, React 19, TypeScript, Tailwind CSS 4, shadcn/ui
- **API Routes**: серверные эндпоинты с динамической обработкой CORS
- **Имитация**: `X-Simulated-Origin` — эмуляция кросс-доменного запроса с одной страницы
- **Темы**: `next-themes` — переключение между светлой и тёмной темой
- **Деплой**: Vercel (serverless-функции для API)
